── SAVE LOGIC ──────────────────────────────────────────────────
ENTRY:   _data.py → SimpanData() → scripts/Transaction/GeneralTransaction.py → CreateTransaction('CA', ...)

ALUR LENGKAP (scripts/Transaction/GeneralTransaction.py baris 61-97):

  1. config.BeginTransaction()
  2. GetBatch(helper, ActualDate)
     → BatchHelper.GetBatchUser(ActualDate) → cari/buat TransactionBatch aktif
  3. oBatch.NewTransaction('CA')
     → Transaction baru dengan TransactionCode='CA'
  4. oHistory = helper.CreatePObject('TransHistoryOfChanges')
     → catat history perubahan
  5. ExecFunction('CA', helper, oTran, oBatch, request, params)
     → fungsi CashAdvance() di baris 771-886

DALAM CashAdvance() (baris 771-886):
  a. Set field Transaction:
     - oTran.ReferenceNo, Description, Inputer, BranchCode
     - oTran.Amount = request['Amount']
     - oTran.CurrencyCode = DefaultCurrency (dari SysVar 'OPTION.DefaultCurrency')
     - oTran.ReceivedFrom = request['ReceivedFrom']
     - oTran.ActualDate = oBatch.GetAsTDateTime('BatchDate')
     - oTran.TransactionDate = request['TransactionDate']

  b. Lookup/Create EmployeeCashAdvance account:
     - helper.GetObjectByNames('EmployeeCashAdvance',
         {'EmployeeId': employeeId, 'CurrencyCode': DefaultCurrency, 'BranchCode': BranchCode})
     - Jika belum ada → CREATE baru:
         helper.CreatePObject('EmployeeCashAdvance', [BranchCode, DefaultCurrency, employeeId])
         oAccount.AccountName = request['EmployeeName']
       → INSERT ke tabel transaction.ACCOUNTRECEIVABLE dengan AccountReceivableType='C'

  c. Buat TransactionItem untuk EmployeeCashAdvance:
     - oTran.CreateCATransactItem(oAccount)
     - oItemCAD.SetMutation('D', Amount, 1.0)   ← DEBET pada rekening UM karyawan
     - oItemCAD.SetFundEntity(request['FundEntity'])  ← default 4=Amil
     - oItemCAD.SetJournalParameter('10')
     - Jika HasCAReturnInfo: link ke existing return item

  d. Buat BudgetTransaction (jika BudgetId != 0):
     - oItemCAD.CreateBudgetTransaction(oBudget.BudgetId)

  e. Buat CashAdvanceMemoInfo (jika RealMemoId != 0):
     - INSERT ke tabel transaction.CASHADVANCEMEMOINFO
       (TransactionId, TransactionItemId, RealMemoId)

  f. Buat TransactionItem untuk CashAccount:
     - helper.GetObject('CashAccount', CashAccountNo)
     - oTran.CreateAccountTransactionItem(oCashAccount)
     - oItemCA.SetMutation('C', Amount, 1.0)    ← KREDIT pada kas/bank
     - oItemCA.SetJournalParameter('10')

  g. oTran.PaidTo = oAccount.AccountName

  h. oTran.GenerateTransactionNumber(oCashAccount.CashCode)
     → format: KK-{YYYY}-{branchCode}-{cashcode}-{seq7digit}
     → INSERT ke seq_transactionnumber untuk dapat sequence

  i. oTran.SaveInbox(params)

  j. FileKwitansi = oTran.GetKwitansi()
     → generate file Word kwitansi dari template

  6. Check auto-approval:
     corporate.CheckLimitOtorisasi(oTran.Amount * Rate)
     → jika Amount <= limit → oTran.AutoApproval() (AuthStatus='T')
     → jika Amount > limit → tetap AuthStatus='F' (perlu otorisasi manual)

  7. oTran.CreateJournal()
     → INSERT ke accounting.JOURNAL entries (debit UM karyawan, kredit kas/bank)
     → jika status == 2 → raise Exception (rollback)

  8. oHistory.TransactionNo = oTran.TransactionNo
  9. config.Commit()
  10. Jika Exception → config.Rollback()

── SCHEMA DB ───────────────────────────────────────────────────
ENTITIES:
  - Transaction → tabel: transaction.TRANSACTION
    kolom: transactionid (PK), transactiondate, referenceno, description,
           inputer, transactioncode, branchcode, authuser, transactiontime,
           authdate, authstatus, isposted, actualdate, amount, currencycode,
           batchid (FK), paidto, receivedfrom
    DISCRIMINATOR: transactioncode = 'CA' → Penyerahan Uang Muka

  - EmployeeCashAdvance → tabel: transaction.ACCOUNTRECEIVABLE
    kolom: accountno (PK, FK ke financialaccount), accountreceivabletype,
           employeeid, employeeidnumber
    DISCRIMINATOR: accountreceivabletype = 'C' → Uang Muka Karyawan
    Inherits dari: AccountReceivable (accountreceivabletype='R') →
                   FinancialAccount (financialaccounttype)

  - CashAdvanceTransactItem → tabel: transaction.ACCOUNTTRANSACTIONITEM
    kolom: transactionitemid (PK), cattype, accountno, accounttitype
    DISCRIMINATOR GANDA:
      - accounttitype = 'C' → Cash Advance (dari AccountTransactionItem base)
      - cattype = 'D'       → Penyerahan (CATransactItem)
      - cattype = 'C'       → Pengembalian (CAReturnTransactItem)

  - CATransactItem → tabel: transaction.ACCOUNTTRANSACTIONITEM (subset)
    kolom: transactionitemid (PK/FK ke CashAdvanceTransactItem),
           returntransactionitemid (FK ke CAReturnTransactItem),
           distributiontransferid (FK ke DistributionTransferInfo)
    DISCRIMINATOR: cattype = 'D'

  - CashAdvanceMemoInfo → tabel: transaction.CASHADVANCEMEMOINFO
    kolom: transactionitemid (PK), realmemoid, transactionid
    Relasi: link optional ke tabel realmemo (memo penyaluran)

  - TransactionBatch → tabel: transaction.TRANSACTIONBATCH
    kolom: batchid (PK), batchno, batchdate, description, inputer,
           isclosed, isposted, batchtag

RELASI:
  - Transaction.BatchId → TransactionBatch.BatchId (FK)
  - CATransactItem.AccountNo → EmployeeCashAdvance.AccountNo (FK via FinancialAccount)
  - CATransactItem.ReturnTransactionItemId → CAReturnTransactItem.TransactionItemId (optional FK)
  - CashAdvanceMemoInfo.TransactionId → Transaction.TransactionId (FK)
  - CashAdvanceMemoInfo.RealMemoId → (tabel realmemo, domain penyaluran)

── DISCRIMINATORS ──────────────────────────────────────────────
  KRITIS — jangan hilangkan saat implementasi:

  1. transaction.TRANSACTION.transactioncode = 'CA'
     → Membedakan transaksi Penyerahan Uang Muka dari semua jenis transaksi lain
     Source: GeneralTransaction.py baris 32, _data.py baris 76

  2. transaction.ACCOUNTRECEIVABLE.accountreceivabletype = 'C'
     → Membedakan rekening Uang Muka Karyawan dari jenis piutang lain
     ('E'=Piutang Karyawan, 'D'=Piutang Non-Karyawan, 'C'=Uang Muka/Rekap)
     Source: app.mdt baris 3411-3418 (EmployeeCashAdvance inherits AccountReceivable dengan ClassifierStringValue='C')
     Source laporan: fSummaryEmpCA_data.py baris 38, fListEmployeeCA_data.py baris 126

  3. transaction.ACCOUNTTRANSACTIONITEM.accounttitype = 'C'
     → Membedakan item Cash Advance dari jenis AccountTransactionItem lain
     Source: fListEmployeeCA_data.py baris 126: "WHERE A.ACCOUNTTITYPE = 'C'"

  4. transaction.ACCOUNTTRANSACTIONITEM.cattype = 'D'
     → Membedakan item Penyerahan (CATransactItem) dari item Pengembalian (CAReturnTransactItem)
     Source: fListEmployeeCA_data.py baris 127: "AND CATTYPE = 'D'"
     Source: app.mdt baris 3532 (CATransactItem ClassifierStringValue='D')
     Source: app.mdt baris 3480 (CAReturnTransactItem ClassifierStringValue='C')

  5. request['FundEntity'] = 4 (Amil)
     → Default sumber dana Amil, di-hardcode saat open form
     Source: _intr.py baris 32: "self.uipTransaction.FundEntity = 4"
     Map: {1:Zakat, 2:Infaq, 3:Wakaf, 4:Amil, 5:Non-halal}
     Tersimpan di: ACCOUNTTRANSACTIONITEM via SetFundEntity()

  6. transaction.TRANSACTION.authstatus
     'F' = Belum Otorisasi (perlu approval jika > limit)
     'T' = Sudah Otorisasi (auto-approve jika <= limit Corporate)
     Source: GeneralTransaction.py baris 82-84, corporate.CheckLimitOtorisasi()

               t.description, t.inputer, t.branchcode, t.authstatus,

        JOIN transaction.accountreceivable ar ON ar.accountno = ati.accountno

          AND ati.accounttitype = 'C'
          AND ati.cattype = 'D'

== CATATAN TAMBAHAN ==

1. JANGAN pernah ubah nilai FundEntity=4 (Amil) — ini hardcoded di legacy
   dan menentukan kode akun jurnal yang benar.

2. HasReturnTrans / cattype check WAJIB diimplementasi di endpoint GET:
   jika transaksi sudah memiliki LPJ (CAReturnTransactItem terkait),
   form edit harus disable field Amount, CashAccount, Employee.

3. Auto-create EmployeeCashAdvance: jika karyawan belum punya rekening UM,
   INSERT baru ke ACCOUNTRECEIVABLE dengan accountreceivabletype='C'.
   Di isf-app, ini dihandle di dispatcher saat AUTHORIZED.

4. Budget optional: BudgetId=0 berarti tidak ada budget — JANGAN validasi
   jika kosong.

5. Memo Penyaluran optional: RealMemoId=0 berarti tidak terkait memo —
   jangan buat row CASHADVANCEMEMOINFO jika RealMemoId=0.

6. Nomor transaksi format: KK-{YYYY}-{branchCode}-{cashCode}-{seq7digit}
   → gunakan nextval('seq_transactionnumber') di DB.

7. QAC dan SPVACC muncul di laporan tapi tidak di form transaksi —
   pertimbangkan apakah perlu role tersendiri di isf-app atau cukup ACC.
   AMBIGU: QAC tidak ada di mapping role code isf-app — laporkan ke nuwis-architect.
