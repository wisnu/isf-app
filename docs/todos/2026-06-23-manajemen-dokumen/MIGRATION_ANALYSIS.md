```sql
  LEFT JOIN JenisDokumen c ON b.IdJenisDokumen = c.IdJenisDokumen
WHERE b.TipeDokumen = 'K'
  AND b.TanggalDokumen >= '{tglawal}'
  AND b.TanggalDokumen <= '{tglakhir}'
  [AND b.IdJenisDokumen = {IdJenisDokumen}]  -- jika IsAllJenisDokumen='F'
```

## Otorisasi Workflow

Tidak ada. Modul Manajemen Dokumen di legacy personalia DAF tidak menggunakan
workflow approval (maker-checker). Save langsung ke database via `config.Commit()`
tanpa melalui `otorisasi.submission`.

Evidence:
- `fDokumenMasuk_data.py:Simpan` — `config.BeginTransaction()` → `config.Commit()` langsung
- `fDokumenKeluar_data.py:Simpan` — idem
- Tidak ada reference ke `otorisasi` module atau `save-and-submit` pattern

Rekomendasi untuk isf-app: implementasi CRUD langsung (tanpa otorisasi) adalah
tepat untuk modul ini.

```
              |                     |
        DokumenMasuk          DokumenKeluar
              |
          LsDisposisi (list Disposisi)

DokumenKeluar ──> WorkUnit (enterprise schema)
```

- `DokumenMasuk` dan `DokumenKeluar` tidak saling ber-FK
- `DokumenKeluar` ber-FK ke `WorkUnit` (enterprise schema) — cross-schema join
- `Disposisi` adalah child list dari `DokumenMasuk` (delete-cascade saat edit: `DeleteAllPObjs()`)
